# Workstream milestones

This is a proposed sequence within the course's seven-week limit, not a dated
course calendar. Course start/end dates have not been supplied. Task status
lives only in `checklist.md`; each milestone advances on evidence, not elapsed
time.

| Milestone | Objective and deliverable | Exit gate |
| --- | --- | --- |
| M1: Setup, evidence and threats | Verified development setup, dataset inventory, validated schema/run provenance, reviewed threat model | Resolve or explicitly bound run/date uncertainty; Gaurav reviews threat assumptions |
| M2: Evaluation contract | Reviewed evaluation protocol and small audit/evaluation utilities with pytest coverage | Agree grouping, development/test split, feature eligibility, metric aggregation and undefined metrics before comparison |
| M3: Shortcut audit | Reproducible diagnostic scripts and interpretation using Nitendra's outputs or agreed baseline interface | Same folds across feature comparisons; identify non-identifiable date/class comparisons; report supported and unavailable contrasts |
| M4: Selective prediction | Reviewed abstention specification, simple telemetry-quality/policy code and tests | Agree inputs and reason codes; select thresholds using validation only; account for abstained attacks |
| M5: Paired robustness | Paired clean/degraded evaluation | Marco's agreed scenarios and Nitendra's scores integrated; independent-run uncertainty and coverage reported |
| M6: Report and reproducibility handoff | Capstone-ready methods, results, limitations and reproduction instructions | Claims traced to artifacts; documented commands/configuration reproduce supported analyses; Gaurav reviews final material |

Avoid a new model training framework, full O-RAN simulator, or dashboard.
Dataset availability and independent benign-run support determine which
comparisons are feasible; reduced scope requires Gaurav's decision.
